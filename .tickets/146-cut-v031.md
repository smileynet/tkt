# Release v0.4.0: ship post-v0.3.0 workflow changes safely

> Source: #128 (2026-08-23 architecture audit) P0/P1/P2 findings, decomposed into fix tickets.

## What to build

Cut v0.4.0 once the correctness and release-readiness blockers below are closed. It
ships the already-merged post-v0.3.0 user-facing workflow improvements together with
the fixes needed to make the ticket contract safe. v0.3.1 was never tagged and is
intentionally skipped; this is a minor release because the unreleased history includes
new user-facing commands, targets, and workflow capabilities.

Blocking fixes (each references its #128 finding):

- **#131** — F1: block-style `blocked_by` parsed as empty; lint rewrite data loss (P0)
- **#132** — F2: common hand-edits eject tickets from corpus (P0) — *done*
- **#133** — F3: `yaml_scalar_unescape` corrupts plain scalars (P0)
- **#134** — F4: renumber ignores birth-window citation scan (P0)
- **#135** — F5: JSON error envelope not last line of stderr (P1)
- **#136** — F6: global `--dry-run` ignored by 7 mutating commands (P1)
- **#137** — F7: `origin/main` hardcoded in race detection (P1)
- **#139** — F10: evidence gates partially dead (P2)
- **#141** — F11: `[X]` checkboxes invisible to AC stats (P2)
- **#152** — residual parser defect: an indented frontmatter comment can corrupt the
  preceding field value. This is another hand-edit contract violation and must be fixed
  before the release.
- **#181** — verify atomic writes on Windows and Linux before relying on the cross-platform
  storage guarantee.
- **#188** — reject duplicate frontmatter keys rather than silently selecting or discarding
  one authoritative-looking value.
- **#189** — remove contradictory `env`/`requires` eligibility so ready work cannot disappear
  through incompatible filters.

Additional release-readiness work found in the 2026-10-19 review:

- **#150** — make `doctor --strict` agree with `validate --strict`; a health command
  must not report a clean corpus while strict validation fails.
- **#160** — decide the ratchet for 27 legacy missing-resolution warnings so strict
  validation is meaningful rather than permanently noisy.
- **#185** — restore push/PR CI; local checks are necessary but the accepted
  enforcement policy names CI as the release boundary.
- **#201** — correct the agent-facing help, package metadata, and curated changelog
  process so the release accurately describes what users receive.
- **#204** — parse one-item block-style dependencies so the frontier and renumber
  birth-window checks cannot silently miss a citation.

## Scope decision (2026-10-19)

The unimplemented agent-experience, native-relations, and cross-harness deployment
features are deferred to v0.5.0. They do not block the release of the behavior already
merged since v0.3.0. This decision does not waive any blocker listed above; every
deferred open ticket is identified in `docs/plan.md`.

Package and plugin metadata now declare 0.4.0; do not tag, publish, or roll the
`Unreleased` changelog section until all blockers are closed and the release protocol
has completed.
